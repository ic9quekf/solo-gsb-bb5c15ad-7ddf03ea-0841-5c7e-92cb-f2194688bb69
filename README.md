# API 网关路由歧义排查工具

粘贴多条路由规则（静态段、`:param` 单段参数、`*` 零或多段通配、优先级数字），
系统自动找出可能同时命中的规则对，生成最短具体请求路径作为冲突见证，
并按「优先级数字越大越先、平手按输入顺序」模拟最终命中。
支持勾选禁用单条规则即时重算，并可导出包含冲突对、见证路径与胜出规则的 JSON。

## 变更影响模式

切换到「变更影响」标签后，当前规则自动作为基线，可再粘贴一份候选规则与请求样本
（每行 `[次数] 路径`，次数省略时为 1，`#` 开头为注释），系统用同一套匹配语义
逐条计算两套规则下的胜出规则（规范化模式与优先级均相同才视为同一规则），按
「命中迁移、新增命中、变为未命中、无变化」分类并汇总受影响请求次数。
非法样本逐行提示且不参与统计；页面支持按分类筛选、查看基线/候选胜出规则与次数，
并可导出本次影响明细 JSON。规则或样本变化时自动防抖重算。

## 最小复现包

在「冲突分析」标签的规则表「复现」列勾选 2～20 条启用且合法的规则，后端以所选
规则之间已有的去重冲突见证路径为候选，重新计算每条路径实际命中的规则与覆盖的
冲突对，再用确定性分支限界精确选出覆盖全部冲突对的最少路径集合（并列时依次按
路径总段数、排序后的路径字典序决胜，不做贪心近似，也不按冲突逐条保留见证）。
页面展示每条入选路径、实际命中规则与覆盖的冲突对，并可下载复现包 JSON；
包内胜出模拟限制在所选规则内，保证复现包自包含。

## 优先级修复模式

切换到「优先级修复」标签后，在当前规则基础上逐行填写修复期望：

```
请求路径 => 期望胜出规则ID
```

`=>` 两侧可留空格，`#` 开头为注释。后端对每条合法期望先模拟当前命中
（优先级数字越大越先、平手按输入顺序），再让期望规则与同路径命中的每个对手
形成一条 0/1 差值约束：目标当前已胜出为 0 差（新优先级不低于对手即可），
当前落后为 1 差（必须严格超过）。全部约束与「只允许提高整数优先级」
（`新优先级 ≥ 当前优先级`）合并为差分约束系统统一求解：

- 用强连通分量识别闭环：分量内出现 1 差边即正权环，意味着相关期望互相要求
  严格超过，只抬优先级无解，页面返回一组构成闭环的冲突期望（标注每条边由
  哪些输入行推导）；
- 零差约束在分量内合并取值，缩点后的 DAG 上取最长路径，得到**逐项增幅最小
  的确定性整数方案**（每条规则都恰好取满足所有约束的最低值，结果唯一）；
- 非法路径、路径未命中任何规则、目标规则不存在/已禁用/自身非法、目标规则
  不匹配该路径，均逐行提示且不参与求解；
- 页面展示调整前后优先级与增幅、每条期望调整前/后的胜出规则及验证结果，
  并支持下载建议 JSON（含逐条约束、验证结果与闭环冲突详情）。

规则或期望变化时自动防抖重算。例如下列规则：

```
10  /api/users/new
100 /api/users/:id
1   /api/*
0   /health
```

填入 `/api/users/new => R1` 后，`R1` 需要严格超过 `R2(100)`，方案给出
`R1: 10 → 101`（对 `R3` 仅为 0 差，不会多抬）；而 `/health => R4`
本就满足，增幅为 0。若同一路径既期望 `R1` 胜出又期望 `R2` 胜出，
则返回正权环冲突，不产生建议。

## 启动

```bash
docker compose up --build
```

## 访问

- 地址：http://localhost:8080 （端口 `8080`）

## 配置

- `PORT`：服务监听端口，默认 `8080`；修改后需同步调整 `docker-compose.yml` 的端口映射。

技术栈：TypeScript + React（Vite）前端、Express 后端；镜像由根目录 `Dockerfile` 多阶段构建，依赖安装与初始化均在容器构建/启动时完成。
